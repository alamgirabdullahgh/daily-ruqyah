# হ্যান্ডঅফ: চিকিৎসার আয়াত হাতে-পড়ে মার্কিং (ডেইলি রুকইয়াহ)

## কাজটা কী
ডায়াগনোসিসে (রোগ নির্ণয় / শারীরিক রোগ) প্রতিটি রোগের নিচে **“📚 চিকিৎসা”** চাপলে সংশ্লিষ্ট সব আয়াত আসে। আগে প্রতিটি আয়াতে কতটুকু আরবি/বাংলা মার্ক (সোনালি/হাইলাইট) হবে আর অডিও কতটুকু কাটবে — সেটা লজিক (ওয়াক্ফ চিহ্ন, বাক্য-শুরুর শব্দ) দিয়ে ঠিক হতো; তাতে **অনেক ভুল**: অর্থের সাথে মেলে না, আরবির শুরু-শেষ ঠিক নেই, আরবির সাথে বাংলা মার্ক মেলে না।
ব্যবহারকারীর নির্দেশ: লজিকের ওপর ভরসা না করে **আয়াত বাই আয়াত পড়ে** ঠিক করতে হবে — কোন আয়াতের কতটুকু সমস্যার সাথে সংশ্লিষ্ট, আরবি কতটুকু পড়া হবে, বাংলা কতটুকু মার্ক হবে। তারপর সেটাই ডেটাতে বসবে।

## কাজের পরিধি
- `worklist.json` = সব কাজ: ১,১১৮টি আয়াত / ১,৪৮০টি (আয়াত+মিলে-যাওয়া-শব্দ) জোড়া (ডায়াগনোসিস ১,১০১ + শারীরিক রোগ ৯২ আয়াত, কিছু মিল)।
- এর মধ্যে ১২৪ জোড়া আগে থেকেই `data/quran-meaning-cuts.json`-এ হাতে করা আছে (`curated:true`)। সেগুলো `show.js` বাদ দেয়; পরে সময় থাকলে পুনর্মূল্যায়ন করো।
- কাজ কতটুকু বাকি: `node tools/treat-marking/show.js 1` — শেষ লাইনে বাকি সংখ্যা। `PROGRESS.md`-ও দেখো।

## ফাইল ও টুল (`tools/treat-marking/`)
| ফাইল | কাজ |
|---|---|
| `worklist.json` | কাজের তালিকা (পরিবর্তন করবে না)। প্রতি আয়াতে `ws` = মিলে-যাওয়া আরবি শব্দ-নম্বর (`w`), পুরনো স্বয়ংক্রিয় সীমা (`auto`), `terms` = কোন বিষয়ে এসেছে। |
| `show.js [n] [শুরু-আইডি]` | পরের n টি বাকি আয়াত দেখায়: নম্বর-সহ আরবি শব্দ, শব্দার্থ, বাংলা অনুবাদ (শব্দ-নম্বর সহ), বিষয়। |
| `marks/NNN.json` | **তোমার কাজের ফল** (মূল উৎস)। প্রতি ব্যাচে ~২৫-৪০ আয়াত। ফাইল-নাম ক্রমিক: 001, 002, … |
| `check.js [নামাংশ]` | প্রতিটি মার্কের আরবি অংশ + অ্যাপ বাংলায় ঠিক কোন অংশ মার্ক করবে — পাশাপাশি দেখায়। অমিল এখানে ধরা পড়ে। |
| `apply.js` | marks যাচাই করে `data/quran-meaning-cuts.json`-এ বসায় (অ্যাপ এই ফাইলই পড়ে)। ভুল থাকলে কিছুই লেখে না। |

## মার্ক ফরম্যাট
```json
{"marks":[
 {"id":"2:102","w":[38],"tr":[37,51],"bn":[a,b],"note":"কেন এই সীমা (এক লাইন, বাংলা)","topic":"বিচ্ছেদের জাদু","rel":"ok"}
]}
```
- `id` = সূরা:আয়াত; `w` = যে মিলে-যাওয়া শব্দ-নম্বর(গুলো) এই মার্ক ঢাকে (worklist-এর `ws[].w` থেকে; **সবকটি w-এর জন্য মার্ক লাগবে**)।
- `tr` = [শুরু, শেষ] **আরবি শব্দ-নম্বর** (১-ভিত্তিক, সীমাসহ)। `w` অবশ্যই `tr`-এর ভেতরে।
- `bn` = [শুরু, শেষ] **বাংলা অনুবাদের শব্দ-নম্বর** (১-ভিত্তিক; show.js-এ নম্বর দেওয়া থাকে)। এটা দিলে অ্যাপ স্বয়ংক্রিয় সারিবদ্ধকরণ বাদ দিয়ে এটাই মার্ক করে। **সবসময় দাও** (স্বয়ংক্রিয়টা প্রায়ই ভুল: যেমন ২:৭-এ আরবি “খাতামাল্লাহু আলা কুলূবিহিম” মার্ক করলে বাংলায় কানের অংশ পর্যন্ত চলে যায়)।
- `note` = ছোট বাংলা টীকা। `rel` = `ok` | `weak` (শব্দ মিলেছে কিন্তু আয়াতের মূল বিষয় এটা নয়) | `off` (প্রসঙ্গই আলাদা; ব্যবহারকারী পরে বাদ দেবে কিনা ঠিক করবে — তুমি আয়াত বাদ দেবে না, শুধু মার্ক করবে ও `rel` লিখবে)। `rel` ডেটাতে যায় না, শুধু marks-এ থাকে।

## মার্কিংয়ের নিয়ম (ব্যবহারকারী যা চান)
1. **অর্থ আগে।** আয়াতের আরবি, শব্দার্থ ও বাংলা অনুবাদ পড়ে বোঝো ওই রোগ/বিষয়ের সাথে আয়াতের কোন অংশটুকু সংশ্লিষ্ট। শুধু সেটুকুই `tr`। আয়াতের অন্য ঘটনা/শাস্তি/উপদেশ বাদ।
2. **সম্পূর্ণ অর্থবহ বাক্যাংশ।** শুরু হবে বাক্যাংশের স্বাভাবিক শুরুতে (কর্তা/ক্রিয়া/শর্ত/মাউসূল), শেষ হবে ভাবের স্বাভাবিক শেষে। ক্রিয়া বা কর্ম মাঝপথে কেটো না; মুযাফ–মুযাফ ইলাইহি, সিলা–মাউসূল আলাদা করো না। সাধারণত ৩–১২ শব্দ, সর্বোচ্চ ~১৫।
3. **আরবি–বাংলার সামঞ্জস্য।** `tr` এমনভাবে বাছো যেন তার বাংলা সঙ্গী অনুবাদে **একটানা** পড়ে। অনুবাদ কখনো শব্দক্রম ওলটায় বা দুই অংশ মিলিয়ে লেখে — তখন আরবি সীমা একটু বাড়াও/কমাও যাতে বাংলা অংশও পরিষ্কার একটানা হয় (উদাহরণ: ২:৭-এ আরবি ১–৬ ↔ বাংলা ১–৯)। সম্ভব না হলে আরবি পূর্ণ বাক্যাংশ রাখো, বাংলা `bn` সবচেয়ে ছোট যে একটানা অংশে অর্থ পুরো আসে সেটা।
4. একই আয়াতে একাধিক `w` আলাদা বাক্যাংশে পড়লে আলাদা মার্ক; একই বাক্যাংশে পড়লে একটি মার্কে `w:[..]`।
5. যা বুঝতে পারছ না, অনুমানে মার্ক কোরো না: `rel:"weak"` দিয়ে সবচেয়ে ছোট নিরাপদ বাক্যাংশ নাও এবং `note`-এ সন্দেহ লিখো।
6. আয়াত/অনুবাদ/শব্দার্থ অন্য কোথাও থেকে নকল বা মুখস্থ বসাবে না — শুধু `show.js`-এর আউটপুট পড়ে ঠিক করো।

## প্রতি ব্যাচের কাজের ধারা
```bash
cd daily-ruqyah
node tools/treat-marking/show.js 25          # ২৫টি বাকি আয়াত পড়ো (বা 15, ঝামেলার আয়াতে কম)
# -> tools/treat-marking/marks/NNN.json লেখো (পরের ক্রমিক নম্বর)
node tools/treat-marking/check.js NNN         # আরবি-বাংলা অংশ চোখে দেখে মেলাও; ভুল হলে marks ঠিক করো
node tools/treat-marking/apply.js             # data/quran-meaning-cuts.json হালনাগাদ
# PROGRESS.md-এ ব্যাচ নম্বর ও বাকি সংখ্যা লিখো
git add -A && git commit -m "মার্ক ব্যাচ NNN: <সূরা:আয়াত> থেকে <সূরা:আয়াত>" && git push
```
প্রতি ২–৩ ব্যাচ পরপর পুশ করো, যাতে লিমিট শেষ হলেও কাজ হারায় না।
**ক্যাশ:** একসাথে অনেক ব্যাচ হলে (বা কাজ শেষে) `app.js`-এ `quran-meaning-cuts.json?v="+DV+"m4"`-এর `m4`→`m5`… আর `sw.js`-এর `dr-shell-vNN` এক বাড়াও, নইলে ফোনে পুরনো ডেটা ক্যাশে থেকে যায়।

## অ্যাপে যা বদলানো হয়েছে (এই কাজের জন্য)
- `app.js`: মার্কে `bn:[শুরু,শেষ]` থাকলে বাংলা হাইলাইট সেটাই (আগে শুধু স্বয়ংক্রিয় `bnPortion`)। আরবি গোল্ড মার্ক ও অডিও কাটা `tr` থেকে (আগের মতো)।
- বিদ্যমান `dg` (রোগ নির্ণয়ের কাটা) ও পুরনো `tr` এন্ট্রি অক্ষত।

## সীমাবদ্ধতা
- বাংলায় শুধু **একটানা** একটি পরিসর মার্ক হয়; দুই ভাগে ছড়ানো অনুবাদে (যেমন “আল্লাহ তাদের অন্তকরণ … বন্ধ করে দিয়েছেন”) আরবি সীমা সেই অনুযায়ী ঠিক করতে হয় (নিয়ম ৩)।
- ফোনে/ব্রাউজারে চালিয়ে চোখে দেখা হয়নি — ধাপগুলো `check.js` দিয়ে যাচাই। কাজ শেষে ব্যবহারকারী কয়েকটা আয়াত অ্যাপে দেখে নিলে ভালো।
